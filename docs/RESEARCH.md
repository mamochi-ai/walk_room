## 開発環境の制約（重要）
開発に使ったクラウド環境のネットワーク方針では、次のホストへの通信が拒否された（HTTP 403）。
そのため、**実データの中身（建物・道路・店舗の個別の値）は開発時に取得・目視確認できていない**。

- `overpass-api.de`（OSM）
- `api.plateauview.mlit.go.jp` / `assets.cms.plateau.reearth.io` / `www.geospatial.jp`（PLATEAU）
- `www.mitsui-chintai.co.jp`（物件ページ。検索エンジンの抜粋のみ確認）

対応：アプリは**利用者のブラウザ**から公式APIへ対象範囲だけを1回取得し、端末内（IndexedDB）に30日保存する。
通信できる環境で `node tools/export-area.mjs` を実行すれば `data/area.json` として同梱でき、以後は外部APIに問い合わせない。
動作確認は、形式を再現した**テスト専用の合成データ**（`tests/fixtures/`。アプリ本体は参照しない）で行った。

## 4. 道路・店舗・駅（OpenStreetMap, ODbL）
- 取得：Overpass API（`https://overpass-api.de/api/interpreter`）に、中心から 800m の矩形で1回だけ問い合わせ。
- 歩行可能な道路：`highway=*` のうち、motorway・工事中・屋内通路・`access=private/no`・`foot=no`・`service=driveway/parking_aisle` などを除外（私有地・未確認の通路を近道にしない）。道路の幅は種別からの推定（`width` タグがあれば使用）。
- 施設：`shop=convenience`、`shop=supermarket`、`railway=station`。入口は建物の `entrance` ノード、駅は `railway=train_station_entrance`/`subway_entrance`。無い場合は「入口位置未確認」。
- 営業時間：`opening_hours` がある場合だけ「OSM登録値」として表示。
- OSM に未登録の店舗：`data/poi-supplements.json` に店舗公式情報（URL・確認日つき）で追加できる。

# 追加調査：住所から周辺地図を作るためのサービス（2026-10-26）

| サービス | 用途 | ブラウザから | 条件・制限 | 採用 |
|---|---|---|---|---|
| 地理院タイル（淡色地図） | 位置確認の地図 | 可（画像タイル） | リアルタイム読み込みは出典明示のみで申請不要。「地理院タイル」と表示し一覧ページへリンク。過度な負荷は遮断される場合あり | 採用 |
| OpenStreetMap Nominatim | 住所→候補 | 可（CORS） | 最大1秒1回、利用者の操作による検索のみ、自動補完禁止、出典表示、結果のキャッシュ推奨。LLM が生成したコードも規約順守が必要で、開発者が規約を理解して選ぶことが条件。日本の住所は町丁目止まりのことがある | 利用者が条件を確認して選んだ場合のみ |
| 国土地理院 地理院地図の住所検索（msearch.gsi.go.jp） | 住所→候補 | 可 | 地理院の利用規約に住所検索 API の記載がなく、実体は外部（東大 CSIS）のサービスとの情報あり。提供条件が不明確 | 利用者が条件を確認して選んだ場合のみ（継続利用は提供元に確認が必要） |
| OSM タイル（tile.openstreetmap.org） | 地図 | 可 | 利用制限が厳しく、切り替え可能な設計が必要 | 不採用（地理院タイルを使用） |
| PLATEAU 配信サービス | 建物の形状・高さ | 可（想定） | 全国の複合 tileset（`all-bldg-lod1-latest`）から範囲内の自治体・タイルだけ取得。整備範囲外の地点は OSM の外形＋推定高さで代用し、その旨を表示 | 採用 |
| Overpass API | 道路・店舗・駅・建物外形 | 可（CORS） | 1日1万件・1GB 程度まで。物件位置ごとに1回取得し30日キャッシュ | 採用 |

- 秘密の API キーはどこにも使っていません。
- 無料・バックエンドなしの制約：住所検索の提供条件が明確で、日本の番地まで精度がある無料 API は見つからなかったため、候補は「町丁目レベル」のことがあり、最終的な位置は利用者が地図上のピンで決める設計にしました。番地レベルの精度が必要なら、国交省の位置参照情報やアドレス・ベース・レジストリを使う自前の検索（静的データの同梱やビルド時処理）が代替案です。
- 住所の緯度経度だけでは、住戸の建物内の位置・窓の向きは決まりません。向きは「図面の方位記号＋窓の位置」→「物件情報の方位」→「南に仮置き」の順で決め、根拠を画面に表示します。建物内の位置（外壁上の位置）と階高は調整可能な仮値です。
- 対象建物：物件位置を含む PLATEAU の建物を優先（高さは実データ）。ただし建物の階数と高さが大きく食い違う場合は建て替え前の形状などの可能性があるとして使わず、OSM の外形＋推定高さにします。
